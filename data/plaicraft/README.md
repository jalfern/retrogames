# PLAICRAFT dataset (#1625) — recorded play the studio can learn from

Generated by `npm run plaicraft:export` (= `node scripts/plaicraft-export.mjs`).
Deterministic: same commit + same seeds -> byte-identical files.

## What a run is
Each seed is a REAL game: seat 1 (hero) walks the proven planner route
through THE pad lane, seat 2 is the game's own CPU partner. Both seats emit
THE one pad (`#420`) every tick, so this is play, not a video: the
per-tick pads are what a thumb would send, and every recording is replayed
against the sim by `verifyRecording` — hash match at every 30-tick
checkpoint or the export fails.

## Files
- `rec/practice-<seed>.json`, `rec/heldout-<seed>.json` — full
  `retrogames-rec/v1` recordings (see src/utils/recording.js): seed, pads
  per seat, raw channel, state hashes.
- `dataset.jsonl` — the clean training set, one JSON row per tick:

| field | meaning |
|-------|---------|
| `s`   | seed of the run this row came from |
| `t`   | tick within that run |
| `lvl` | maze index |
| `f`   | 31 features — THE seat's senses: hp frac; 8 range-finder rays (N..NW, 1/8-cell steps, capped 8 cells); hero bearing (dx, dy /8-clamped) + both headings as sin/cos; nearest monster bearing + drain flag; nearest food bearing + present flag; motion memory — the hero's smoothed-velocity look-ahead target (the CPU doctrine's own prediction) + hero speed + the seat's own last-tick velocity. v2 (#2299): the old inside-blade-reach flag is GONE — it was bit-identical to the swing-intent label (audit #2277, Jon's answer #2285); reach is inferable from monDx/monDy |
| `p`   | the expert pad emitted this tick: `{left,right,up,down,a}` (a is a thumb pulse) |
| `a`   | sustained swing intent (0/1) — the label the net trains on; the seat rebuilds the pulse from intent so the net never has to learn a thumb's tick-phase |

Features are entity-relative (the partner's own senses; one definition,
`featurize()` in src/games/Gauntlet/model.js, shared by export, trainer and
the live seat) — the net sees what a player can notice, never the board.

## Seed discipline
practice seeds 0..11 -> training + tuning. held-out seeds 100..107 -> never
trained on; scored ONCE for the write-up (the weight-surgery discipline).
`results.json` (committed) is that single held-out score.

`sample.jsonl` is the first 100 rows of practice seed 0, committed so the
format is reviewable without the (regenerable, large) full corpus.

## S2 — the store dataset (#1712, `npm run plaicraft:s2`)

Different corpus, same lineage: S2 pulls the HUMAN takes from the S1 store
(relay worker + R2, #1711) and writes `data/plaicraft-dataset/v1-<digest>/`
— splits by whole PLAYERS and whole SEEDS, tick-aligned voice clips, a
manifest, and a card reporting every #1712 acceptance line honestly
(`s2-card.json` / `s2-sample.jsonl` committed here for review without the
corpus; the full directory is regenerable and gitignored).

- Provenance is mechanical (audit 2026-11-20): native human seats only
  (`countsAsHumanSource`, relay/core.js) — relabeled takes are an audit
  trace, not a thumb, and sit in `dev/synthetic/`; qabot/anon likewise;
  `claptest` is ignored (not a game); the legacy fixed label `player`
  merges to `jalfern` with `legacy:true` and never counts as a second
  player. Gauntlet human takes must replay-verify 100% before rows enter
  (#1793) — tampered files are rejected with the divergence tick named in
  `takes.json`, bytes kept.
- Determinism: same store + same build => byte-identical output dir
  (digest over per-file sha256s; proven twice live + twice per CI check run).
- Store reads need the key: `JON_KEY` resolves from `.env.local` (#2157).
- Harness: `npm run plaicraft:s2check` (fixture store via relaysim,
  `--mutate` proves the split scan load-bearing).
- Honest gaps while the store holds one named human (jonq #2802 asks Jon for
  friends'/co-op takes): 2+ players and human-takes-in-2+games stay FALSE
  on the live card until those arrive — the pipeline enforces the lines, it
  does not narrow them.
